#### Important (Should Fix)

1. **Background does not invalidate the web request generation.** `frontend/src/communication/store.tsx:274` hides/disposes current history but neither aborts the effect controller nor advances an authorization generation. `active()` at line 85 ignores visibility; a pending metadata read can complete, create a new engine, fetch bodies and execute line 194 while the document remains hidden. A focused mounted-hook test reproduced a private conversation being restored after background. Cancel/invalidate all pre-background reads and commands, hide the fetched conversation list as well, and require a fresh foreground authorization generation before publishing anything. Cover delayed metadata/history/command responses, not only background after settled requests.

2. **Removed sources outside loaded history leave web private thread snapshots visible.** `frontend/src/communication/Connect.tsx:181` closes a source only when its ID is found in `chat.messages` with a changed revision/removal. A search/saved target can open `/thread` without entering that array; a subsequent removal emits a changed ID but creates no loaded tombstone. The store increments `privacyEpoch` (`store.tsx:131`), but the new view key at `Connect.tsx:51` no longer consumes that epoch. A focused UI test reproduced the old quote remaining visible after the removal notification. Pass changed source IDs into the view and invalidate every affected source snapshot, including unloaded thread roots/replies, search/saved results and in-flight target loads, while preserving unrelated authored RAM.

3. **A normal deleted message is mistaken for conversation/company revocation during replay.** `frontend/src/communication/history.ts:172` and `mobile/src/conversationSync.ts:188` fetch each created/edited root. If that root was subsequently removed—especially when creation and removal straddle two 100-event pages—the existing `/thread` endpoint legitimately returns 404 (`backend/platform/communication_controls.go:125`). Web treats that as a conversation boundary at `store.tsx:203`; native invokes global policy clearing at `mobile/src/client.ts:127`. Thus ordinary source deletion destroys drafts/history (native clears all company authored input). A focused web hook test reproduced draft loss despite metadata remaining authorized. Distinguish this contextual missing-source response from denied conversation access: immediately scrub the source, revalidate metadata, reconcile/drain through the removal, and reserve hard draft clearing for confirmed permission/history boundaries. Keep genuine 401/403/404 authorization cleanup fail-closed.

4. **Native foreground return waits for the next 15-second poll under real network latency.** `mobile/src/Workspace.tsx:373` starts `restoreEvent()` without sequencing a refresh after it. The foreground effect at line 429 can run first, and `refresh()` returns because `sessionAuthorized.current` is false (line 223). Successful restore changes a ref and a same-ID session, neither a dependency that retriggers this effect. A focused provider test with a deferred session response reproduced `w.foreground === false` after successful restoration; only the later interval can authorize the UI/camera return. Chain session restore into fresh company refresh, with generation guards, and test delayed rather than immediately resolved session responses.

5. **Native route restoration saves an absolute scroll position, not an anchor offset.** `mobile/src/NativeConversation.tsx:457` stores `contentOffset.y`, then line 478 restores that same absolute offset after fresh history hydration. The located anchor ID is only used as an existence check. An edited/wrapped row above the anchor, a removed range or changed viewport makes the user land on a different row/position. `mobile/src/NativeConversation.test.tsx:297` only asserts that the old absolute 745 value is replayed and therefore cannot detect this defect. Store the first visible canonical ID plus its offset relative to the viewport, then position that row using current measured layout and restore the relative offset. Add a regression with changed heights above the anchor; retain physical pixel verification as a separate gate.

6. **Confirmed native success never retires retained form state.** `mobile/src/Publication.tsx:197` saves `pending` to RAM but never clears it after a confirmed successful POST. Reopening that source remains permanently locked to “Retry the same publication” (`:217`, `:388`), preventing selection of another publication mode. `mobile/src/WorkScreen.tsx:119` only closes the creation sheet; since `openCreate()` no longer resets fields (`:93`), a new task starts with the previous successfully submitted title/deadline/reviewer. This contradicts the report's successful-create cleanup claim and risks duplicate new records. Retire the matching confirmed attempt/reset authored form state and retry key on success, without erasing a newer attempt or an ambiguous failed attempt. Add success→reopen tests for both paths.

7. **Intake's new time picker is a nonfunctional control.** `mobile/src/Intake.tsx:162` always passes `time=""`; line 164 discards `v.time`, while line 57 always submits `deadlineMode: "all_day"`. “Use timed deadline,” time entry and the system time picker can never affect the commitment. Either wire company-local time, `workDeadline` and explicit DST choices end-to-end as required for a deadline picker, or expose an explicitly date-only picker for an intentionally all-day flow. Never present an operative time choice and silently save another deadline mode.

8. **Plan-mandated duplication of the transport-neutral history state machine.** `frontend/src/communication/history.ts:1` and `mobile/src/conversationSync.ts:1` duplicate the complete cursor/lane/merge/tombstone/reconciliation implementation, with corresponding nearly identical tests; `frontend/src/communication/drafts.ts:1` and `mobile/src/conversationDrafts.ts:1` similarly duplicate privacy-sensitive state ownership. These are shared business/authorization rules, not platform rendering. The preparation names two files, but that does not make verbatim logic duplication maintainable: every fix above must remain synchronized manually. Extract a single shared neutral implementation (platform files may re-export/adapt it), or use one canonical generated source with enforced parity; retain platform integration tests.
