## Delivered behavior

A. Web/native authored drafts are RAM maps scoped by origin/company/user/conversation/thread. Main/thread compose preserves body, selected mentions and frozen canonical send intent across same-company A/B navigation and temporary background. Synchronous busy locks prevent duplicate taps. Source edits/removals clear presented quotes and panels while retaining original pending payload fields/client ID. Authorship is never saved to localStorage/disk. Native Work creation, task review reason, finance creation/review, publication and intake authored fields use `useRamInput`; only setters cache authored values, never initial fetched defaults. Publication lost confirmation retains its frozen request body and retry key and can retry after remount without reusing cached audience confirmation. Successful Work creation clears inputs; reopening an interrupted form retains them.

Root logout/account/origin/company changes and confirmed authorization/readBasis changes erase input/captures. Native keeps a content-free confirmed authorization fingerprint across background; a fresh changed membership graph clears RAM before redisplay even though fetched work was erased. Native typed policy denial clears private views; ordinary transport failures preserve authored input. Route/provider regressions cover this, not just a mounted conversation mock. Fetched history/evidence/directory are withheld during background and freshly authorized before redisplay. Content-free history bounds/anchor IDs/policy fingerprints can survive in RAM; message bodies and people are refetched.

B. `ConversationHistory` owns separate opaque older and event cursors, serializes bootstrap/sync/older/reconcile/merge, coalesces concurrent sync/older requests, rejects disposed generations and merges by canonical ID/sequence/revision. Cold start first establishes an event baseline, fetches the head, then drains any race delta. Every /sync page is drained; stream hints never become message cursors. Changed message roots are freshly authorized via existing thread GET. Removed/expired rows are immediately scrubbed (body, reply, media, mention fields). Unknown events/explicit overflow reconcile the current loaded range, not merely the newest100. Range reconciliation sorts by server sequence. Metadata permission heartbeat remains15 seconds. Native bearer WebSocket header shape is wired; actual native handshake stays a device gate.

Web and native stream handlers validate conversation/kind/monotonic safe eventSequence, catch up on ready/reconnect, and keep reconnect replay distinct from overflow. Scoped AbortController/client generations and owner identity checks reject delayed old responses. Successful canonical send merges immediately; GET/read commands do not replace the range with the head. Normal route return refetches a previously loaded range and restores its content-free anchor rather than serving offline history.

C. Web records first visible canonical ID/top offset and restores it after prepend/edit/removal/live arrival. Away from bottom shows labelled new-message action; bottom follows. Native conversation, chat list, Work list, threads and people use stable-ID FlatLists; native variable-height anchoring uses maintainVisibleContentPosition and measured-average scroll failure fallback. Composer stays outside the native chat list. Native /read uses the highest actually viewed sequence only at foreground bottom; regression proves fetching100 does not acknowledge100 automatically. Web retains document visibility/alive guards. The web history retains canonical DOM rows; this milestone's explicit windowing replacement is native FlatList, and browser anchor evidence does not certify native windowing.

D. Participant mentions are searchable, selection chips are visible, and main/retry mention fields remain frozen. Loaded mentions explicitly say "Mentions in loaded history" and offer older loading; there is no claim of global mention search. Search/saved/pin navigation carries exact message IDs. Loaded targets scroll/focus; unloaded targets use independently authorized root/thread GET. Body-free native notifications deduplicate event IDs, obtain fresh session/company/conversation authorization and use explicit routes, including cold-start responses. Arbitrary URLs are ignored.

E. Linked task cards obtain current task summaries and independently authorized current sources. Periodic refresh, work hints and source changes invalidate snapshots; cards with withheld/denied sources disappear during pending reauthorization. Cards show current title/status/deadline and publication/current source revisions with out-of-date notice. Web opens the existing task workflow and can open precise current sources. Native `/task/[id]` loads a targeted task outside the list, hides old detail while pending, hydrates all bounded evidence pages through the reviewed read helper, uses existing version preflight/review/status/evidence actions, and returns through the stack to freshly restored conversation history. No second task engine or company-rank bypass was added.

F. SDK57-installed DateTimePicker uses company IANA `timeZoneName` and extracts company local fields; existing `workDeadline` performs final timed/all-day/DST validation with explicit fold choices. Cancellation preserves values. Searchable authorized PersonPicker excludes inactive/viewer users and selected owner from reviewer choices, clears invalid selection and displays role/available department context. Work, publication and intake use these primitives.

G. ImagePicker/DocumentPicker copy explicitly selected images/files to owned cache previews bound to origin/company/user/target before invoking the OS UI. Permission denial/cancel, unsupported/HEIC/empty/oversize and changed scope refuse adoption. Return waits for fresh authorization of original destination. Android pending output recovers only when its original RAM destination still exists; process death/revocation cannot invent a target. Preview/discard and destination-labelled uploads are explicit. Chat camera uses the existing reserve/hash/upload/finalize/canonical-message pipeline, retaining reservation/message identity/file through ambiguous confirmation. Task evidence/receipt multipart uses `file`, bearer authorization and expo/fetch FormData without a manual boundary/JSON content type. Additive append failures preserve preview and block repeat until explicit Recheck refetches current record; another upload is deliberate and may duplicate evidence because those APIs have no retry key. Successful receipt append resets finance confirmation and refreshes detail/list; no approval/amount/OCR inference.

H. Page/Sheet handle safe areas, keyboard avoidance, non-scroll virtualized bodies, wrapping controls, accessible names/states and44px Action dimensions. Web shell now measures actual viewport/navigation available height; a real reduced-height runtime caught and fixed composer overlap caused by the old420px minimum. Device accessibility/keyboard performance is not inferred from DOM. README/security background/draft statements now distinguish fetched private data from authored RAM and current binary limitations.
