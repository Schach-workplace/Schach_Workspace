# Private historical report storage

Historical reports introduced SQL33–37; apply the current full mirrored inventory through SQL58 using the deployment's existing migration owner. Do not run production AutoMigrate. Historical facts and snapshots are durable business history; CSV artifact expiry deletes bytes and link availability only.

Set `REPORT_ARTIFACT_ROOT` to a dedicated private persistent volume, separate from media, frontend static content and public object URLs. Every ancestor must be a real directory; the root is0700 and files0600. Both standalone and Encore accept this setting via `platform.ConfigureReports`. `REPORT_ARTIFACT_TTL_HOURS` defaults to168 and permits1–8760. Local standalone defaults alongside its selected SQLite database; local Encore defaults `.encore/report-artifacts`. Production without configured private storage still supports historical reads and returns `export_unavailable` for new exports.

The dedicated report worker handles one long export at a time with120s maximum generation,60s leases and15s renewal. Separate maintenance runs short passes with10s contexts every60s; at most100 schedules, delivery intents and cleanup records are considered per pass. The existing communication worker remains separate. Startup performs one bounded observation batch after seeding, then report maintenance continues observation. Legacy done tasks never become acceptance episodes.

Standalone signal cancellation joins both worker loops. Encore implements actual `shutdown.Handler` with value `shutdown.Progress`; it cancels both owned loops and joins within ForceShutdown or15s. Storage work observes cancellation. Expired leases recover after restart, with at most5 total attempts and5/10/20/40s retry delays.

Artifact downloads authenticate a session and authorize the complete immutable source manifest before headers and before each64KiB chunk. Locks end before network writes. Denied checks stop later chunks; already written or in-flight bytes and explicitly downloaded/shared copies cannot be recalled. Current-state task CSV uses the same before-headers/before64KiB authority boundaries against its original frozen snapshot and original request session, with exact Content-Length to detect a truncated transfer. It never replaces the snapshot or drops denied rows. Scheduled delivery is only an IDs-only in-app Inbox link, included by the public attention list under the current recipient/company/membership epoch and full-source authorization; no email, external provider, automatic device copy or leadership-scope inheritance.

Provisioned India-region volumes, backup retention, physical devices, signing and capacity remain operator rollout gates; owned fixtures do not certify those.

Native sharing is an explicit exported-copy boundary: after confirmation and a final fresh all-source/session/expiry check, calling Expo Sharing grants the original private temporary file to the OS receiver. Unpublished transfers still cancel and delete on authorization, company, principal, endpoint, or background changes. An already-published handoff retains only its one bounded copy (maximum16MiB) while the sharing promise is pending; it cannot make requests or republish after a scope change. Completion, cancellation, failure, active120-second deadline, or elapsed-time checking on resume deletes that copy; startup removes owned orphan files. Native timers stop while the host is suspended, so120 seconds is an active/resume cleanup deadline, not guaranteed wall-clock erasure during suspension or process death. A granted file may remain in private cache until completion, resume, restart, or OS cache cleanup.

Schedule capture isolates recipient failures with savepoints. Safe diagnostic codes/counts and bounded5/10/20/40-second retry state are durable; a terminal denied recipient does not roll back successful recipients or stop later schedules. Each schedule receives at most5 seconds within the10-second maintenance budget, reserving time for company-locked failure bookkeeping and later candidates. Five whole-schedule transient failures pause that schedule; recipient transient capture failures become terminal after five attempts. Definition or schedule edits reset diagnostics and invalidate obsolete outputs.

Explicit definition/schedule saves require all configured recipients to be active and nonsuspended. Runtime checks owner/configuration eligibility separately from the eligibility and complete source scope of each particular recipient. Departure or suspension retires that recipient's output without pausing healthy recipients' later occurrences. Owner departure/source loss, definition revision, explicit recipient removal, schedule version, and expiry remain their existing wider invalidation boundaries.
