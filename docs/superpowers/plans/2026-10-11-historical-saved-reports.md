## Global Constraints

- “Keep Go/GORM/Encore/PostgreSQL and React/Expo.” “Do not introduce a second task engine, unrestricted global search, autonomous AI approvals or a microservice fleet.”
- “Task changes retain original deadlines, evidence requirements, independent acceptance and optimistic versions.” Finance and goals are untouched.
- “Missing data is never a fabricated 100%.” Legacy history is observed/unknown-before; current CompletedAt does not prove a past independent acceptance event.
- “Idempotent action keys survive transport retries.” All new mutating definition/snapshot/export/schedule routes consume the reviewed M5 canonical business retry contract.
- Current source permission controls every historical output; old owner/reviewer assignments are data, not access grants. Company rank never grants private conversation membership. No private excerpts, finance, task comments, evidence files/metadata or time-entry notes in history, snapshots or CSV.
- State-as-of, genuine acceptance episodes, unique accepted tasks and dated effort have independent semantics. Never sum accumulated ActualHours over state facts or acceptance episodes.
- Original/current on-time denominators exclude absent/invalid deadlines. Timed equality is on time; all-day acceptance uses the company zone captured at the event. Report grouping uses its separately frozen selected zone.
- Frozen snapshots are immutable; any inaccessible included task/reference denies the whole output. A newly generated output can have a different authorized source set.
- Snapshot maximum 10,000 combined drilldown rows and 8 MiB canonical serialized content; CSV maximum 16 MiB, at most 100 rows per batch. No silent truncation. Private artifacts expire after configurable 7 days; fact/snapshot history is not deleted by artifact expiry.
- Saved schedules use first fold instant, next valid gap minute, and at most the latest completed missed occurrence. Generate separately for each recipient; initial delivery is an IDs-only local Inbox link, no email/provider copy.
- Long artifact work runs in a dedicated bounded worker, never the serial communication/revocation loop. Accepted M4 uses a one-second ticker and a thirty-second bounded per-pass context; attention/retention/media run every sixty completed iterations, not on a guaranteed wall-clock interval. Production schema uses appended mirrored SQL; no constructor AutoMigrate.
- Touch targets at least 44 logical pixels; usable 320–430px layouts, safe area/keyboard, large text, labelled controls and recoverable failures. Hide fetched content while same-key access checks are pending; scoped authored inputs stay RAM-only and retain inspected versions.
- Preserve the main application/database. Owned local fixtures validate code; physical devices, distribution signing, India hosting, provider delivery and capacity remain separate rollout gates.

## Review Focus

1. A source outside the displayed page contributes a denominator: removing its visibility denies summary, comparisons, job metadata and download, not merely the row page (Tasks 2–6).
2. A legacy done task is reopened before observation, or a post-migration demo/fixture inserts old done work: no past acceptance or earlier state is invented; coverage remains unknown (Task 1).
3. A task is accepted twice and receives backdated time after acceptance: acceptance episodes, unique tasks, state effort and dated effort remain distinct, with stable original snapshots (Tasks 1–2).
4. Revocation/lease loss happens while a CSV is generated or streamed: final publication is fenced, later chunks stop and orphan cleanup succeeds without holding network writes under company locks (Tasks 4–5).
5. Schedule date falls in a DST fold/gap, owner is inactive, or the app returns after a company switch: one resolved occurrence, no obsolete jobs and no delayed old report content (Tasks 3,5–7).

### Durable data

- `TaskFact`: ID, CompanyID, TaskID, TaskVersion unique; RecordedAt and EffectiveAt server UTC instants (native effective is transaction event time; observed effective is observation time); operation, ActorID and actorKind user/system/observation; provenance native_event/observed_current_state, KnownFrom, unknownBefore; code/title, CreatedAtRaw (display only), owner/reviewer/creator/department/project IDs; status/priority/start date/progress/estimate/actual; requires approval; original/current `{mode,date,at,zone}` and deadline reason; CompletedAtRaw labelled current value; companyPolicyZone; parent/dependency IDs as references. No Description, BlockerReason prose, emails, tags, checklist bodies, comments/evidence/private sources. Version1 or current observed version is not necessarily complete history.
- `TaskHistoryCoverage`: company/task primary key, firstKnownAt, unknownBefore, lastRecordedVersion/stateHash, gap flags. Native-created task has known creation boundary and no unknown-before life; observed task's past remains unknown permanently. Immutable `TaskHistoryGap` rows store company/task/fromExclusive/toExclusive, reason and boundary fact IDs: a discovered skipped-version interval after the last exact known event and before the new exact observation is unknown. Same-version divergence opens an unresolved gap until explicit new observed/native version. Reducer never carries a prior state through such a gap; a later exact state is known again without repairing the intervening past. Immutable facts are never overwritten to repair a gap.
- Exact task acceptance/deadline timestamps retain RFC3339Nano source strings in facts; SQL timestamptz indexing may round to PostgreSQL microseconds and cannot be the authority for exact-boundary lateness. Add `acceptedAtRaw` from persisted Task.CompletedAt and compare its parsed exact instant against captured string commitments; typed acceptedAt is indexing/period navigation only. Native event/observation raw instants may be retained alongside typed SQL instants where needed for deterministic hashes. ### Request and reducer interfaces

Proposed neutral Go inputs: `HistoricalReportRequest{From,To,ReportZone string; Filters ReportDimensionFilters; Basis string}`; `ReportDimensionFilters{OwnerID,DepartmentID,ProjectID string}`; `ResolvedReportPeriod{From,To,Zone string; StartInclusive,EndExclusive time.Time}`. Input accepts only recognized fields, valid dates, IANA zone and supported basis/schema; no future period end beyond observed now. Initial as-of is exclusive period-end boundary; do not add an unbounded arbitrary event query surface.

Proposed transaction helpers:

- `ensureObservedTaskState(tx *gorm.DB, task Task, observedAt time.Time) error`: under existing company/task writer serialization, insert only missing current version observation/coverage; validate exact hash. No acceptance creation. Conflicting same-version hash marks inconsistent coverage and blocks historical use until explicit observed maintenance/new revision.
- `appendTaskFact(tx *gorm.DB, before *Task, after Task, actor ReportFactActor, operation string, eventAt time.Time) error`: persisted after state required; ensure old observed coverage when before exists; one fact after committed task write; create acceptance only genuine old-not-done→done with actual event provenance. Review operation is explicitly independent; operation allowlist distinguishes direct completion and system recurrence.
- `appendTaskTimeFact(tx *gorm.DB, entry TimeEntry, persisted Task, factID string, provenance string, observedAt time.Time) error`: called in same time-write/observation transaction, ID uniqueness prevents duplicated hours; no Note.
- `InitializeReportHistory(ctx context.Context, now time.Time, limit int) (observed int, more bool, err error)`: deterministic bounded100 default/max1000 missing-observation scan with durable progress; company lock before current task reread. Use observed instant at each actual capture. Worker resumes, no startup full-table lock. Scoped snapshot generation observes authorized missing rows in bounded chunks then captures snapshot; large populations fail explicit range limit and retain honest pending/unknown coverage instead of synthesizing data.
- `resolveReportPeriod(from,to,zone string) (ResolvedReportPeriod,error)`: `[local midnight from,local midnight day after to)`, AddDate calendar arithmetic. A period ending before a task's first observation has coverage-only row, no state fact. A gap blocks unknown interval state rather than carrying previous fact across it.
- `reduceHistoricalReport(rows []HistoricalReportRow, period ResolvedReportPeriod) HistoricalReportSummary`: deterministic pure metric membership; timestamps parsed/invalid excluded; never current summary helper.
- `authorizeHistoricalSources(tx *gorm.DB,a *access,snapshotID string) error`: validate company/requester then every manifest task against current taskReadQuery in <=100-ID batches (including coverage/reference rows); if any absent/inaccessible return safe `access_changed`409 without identifying hidden source. Reads authenticate session freshly; worker uses reviewed current actors separately.
- `captureHistoricalReport(ctx context.Context,a *access,input HistoricalReportRequest,definition *ReportDefinitionBasis) (HistoricalReportSnapshot,error)`: authorized scope first, PostgreSQL repeatable-read capture, durable atomic data. Snapshot state/ref membership validation immediately before disclose/commit, with no long locks for artifact work. Native revision edits do not invalidate frozen values while source access remains.

Metric codes: `state.cohort`, `state.done`, `state.blocked`, `state.pending_review`, `state.overdue`, `state.deadline_changed`, `state.actual_hours`; `acceptance.episodes`, `acceptance.unique_tasks`, `acceptance.original_on_time`, `acceptance.current_on_time`, `effort.logged_hours`, `effort.observed_hours`; `coverage.unknown_before`, `coverage.gaps`, `coverage.observed_time`, `coverage.invalid_deadline`. State cohort uses latest known state before cutoff, current-at-that-state due date in selected range, excluding cancelled-as-of. Overdue compares to the cutoff in the frozen report zone; date due on final selected day is overdue only for incomplete work at next midnight. Acceptance uses event instant in period and dimensions at acceptance; cancelled/reopened later doesn't erase it. Unique_tasks uses one row per task with all matching episode IDs, not summed episode count. Effort uses independent entryDate and recordedAt cutoff; `effort.logged_hours` includes native entries only, while `effort.observed_hours` separately sums observed entries available by observedAt and explicitly discloses incomplete historical recording coverage. Filter attribution uses linked time fact task state, observed entry attribution explicitly observation basis. Neither sum counts a state ActualHours value again. Missing/invalid state due dates are excluded with coverage, not counted as perfect. Deadline changed considers mode/date/instant/zone; snapshots cannot invent number of revisions for unknown-before tasks.

Every metric details response has `{code,value,unit,numerator?,denominator?,rate?,coverage,rows,cursor}` with numerator/denominator membership selector. For sum metrics contribution rows have hours and fact IDs; coverage rows have reason, no fabricated zero. Zero denominator -> rate null and “Unavailable”, never100%. Summary has explicit episode and unique task labels. Department slices use the same row membership, never another live query.
