> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task, using the controller's established execution method. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provide explicitly requested voice-note transcripts, selected-source summaries, reviewed action candidates and deterministic report explanations, with current permission checks throughout processing and disclosure.

**Architecture:** Add one source-bound job subsystem to the existing modular Go server, with fixed local faster-whisper/Ollama adapters and a dedicated bounded provider worker. Authorize and capture exact selected sources under short transactions, compute outside locks, then reauthorize before committing or returning any output. Generated candidates enter the existing human publication/business review flows; they never execute work directly.

**Tech Stack:** Existing Go 1.26/GORM/PostgreSQL/SQLite/Encore, React/TypeScript, Expo 57/React Native; isolated local Python/faster-whisper/PyAV and installed digest-verified Ollama. No second task engine or microservice fleet.

## Review Focus

1. A comment/structured-record response changes without its parent task/message version changing: bind exact selected nested evidence and test mismatch independently (Tasks 1–2).
2. A revoked source lies outside the currently loaded chat/report page: whole-output read/export/preview denial and immediate cooperative client hiding (Tasks 2, 5, 8–9).
3. Provider receives more tokens than fit, or uses a cloud alias behind a local endpoint: no truncation, shifting, model substitution, network tools or source dropping (Tasks 4, 10).
4. Successful business write loses its response and source is later edited: canonical result replay remains distinct from invalid stale draft/new-write denial (Task 7).
5. WAV/M4A audio is accepted by the application but decode/cancel fails midway: bounded temp lifecycle, scanner gate, byte-hash checks, no result/business leak and usable manual path (Tasks 3–4, 10).

### Source manifest and hashes

`IntelligenceOperation = transcript | summary | action_draft | report_explanation`.

`IntelligenceSourceRequest {kind,id,parentId?,conversationId?,expectedRevision?,expectedVersion?,expectedContentHash?,selectedFieldSet}`. Supported kinds: message, voice_media, record, task_fields, task_comment, expense_fields, goal_fields, goal_measurement, planning_projection, report_current, report_snapshot, transcript. Each kind has a closed field-set enum; no arbitrary JSONPath/SQL/URL. v1 attachment binaries, arbitrary documents, whole directories and automatic thread expansion are excluded; selected evidence hashes are still tracked when supplied by accepted M7/M8 sources. A transcript reference expands to its original media/message/policy/history bindings, original job sessionRef/UserEpoch and exact transcript result hash; authorize the originating derived job and ALL its roots with inherited expiry, never grant a new retention period or resurrect scrubbed text.

`BoundIntelligenceSource {sourceKey,kind,bindingMode,companyId,id,parentId,conversationId,sequence,revision,version,contentHash,fieldSet,policyVersion,memberEpoch,historyFromSequence,expiresAt,manifestHash,sourceSchemaVersion}` uses `bindingMode: live_revision | immutable_fact | derived_result` plus optional fields by kind with validation that required fields are present. `live_revision` requires current captured version/revision and exact nested evidence; `immutable_fact` requires immutable snapshot/fact IDs and hashes with current ALL-source ACLs, never current Task.Version equality; `derived_result` expands its originating manifest and inherits its lifetime. Server computes all bindings; client expected values detect stale selection. Persist private policy/history/ACL metadata; public DTO returns only currently authorized citation labels/selected revision and limitations, never internal session or membership hashes.
