## Finding

**Important — force the disposable frontend to the disposable API.** `docs/qa/tools/start-isolated-qa.sh:65` builds the frontend with the caller's environment. Although the generated server uses the explicit environment at lines 35–42 and `os.execve` at line 58, that protection does not cover the preceding Vite build. `frontend/src/data/api.ts:3` embeds `VITE_API_URL` as the base for authenticated API requests. `frontend/src/store.tsx:47` selects browser demo mode when `VITE_DATA_MODE` is `demo`. An inherited API base could make the page served at 9080 issue mutations to a retained or staged server; an inherited demo flag could defeat the promised authenticated API fixture. The setup description at `docs/qa/TEST_ENVIRONMENT.md:15`–21 therefore overstates the current isolation.

Concise correction: explicitly set `VITE_API_URL=''` and `VITE_DATA_MODE='api'` for this frontend build, overriding both shell settings and frontend dotenv values. Keep the resulting static frontend served by the new loopback fixture. The documentation should describe this explicit same-origin/API-mode override. This is a QA setup finding, not a new product finding. Root owns the correction and integration.
