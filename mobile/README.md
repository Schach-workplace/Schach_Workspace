# Schach native clients

Expo SDK 57 / React Native clients target native Android and iOS using the same authenticated company API. They include secure sign-in/MFA, company selection, private DMs/groups/channels, search/history/threads/message actions/mentions, scanned file and voice-note upload with durable retry, work review, independent finance decisions, selected task/intake/expense publication, structured acknowledgements/polls/events/decisions, intake triage, attention preferences, lost-device revocation and LiveKit calls.

From this directory:

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run export
npx expo-doctor
npm run prebuild
npm run android
```

LiveKit/WebRTC needs a development build; Expo Go is insufficient. Native directories are generated by Expo config plugins. Never hand-edit them. `plugins/withCallService.js` generates the Android private microphone/media foreground service and its React Native bridge. Java 17, Android SDK/platform/build tools and a device/emulator are required for local Android builds. On macOS, configure Xcode and use `npm run ios`; signed deployment requires the organization's identifiers, certificates/provisioning and provider push setup. Earlier communication verification produced Android ARM64/x86_64 debug APKs and an embedded-bundle evaluation APK. Milestone 3 changed native dependencies/config and verified Android/iOS Hermes exports; the earlier APKs do not contain these changes. A new binary must be rebuilt. Linux did not compile/sign an iOS binary.

For a standalone Android evaluation after `npm run prebuild`, run `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,x86_64` from the generated `android/` directory. The default generated release configuration uses the Android Debug key. The verified evaluation artifact contains `assets/index.android.bundle` and both native ABIs, so it does not require Metro; it requires a real Schach HTTPS origin. Organizational signing, identifiers, push credentials and physical acceptance remain mandatory before distribution. Never commit generated keystores or provider secrets.

Enter the actual Schach HTTPS origin at sign-in. Release clients reject HTTP, URL credentials and unsafe endpoint paths; developer HTTP is only for explicit local evaluation. Native bearer sessions use platform secure storage. No bearer credential is placed in a URL. Temporary background cancels old request generations and hides fetched private history/evidence. Foreground return requires fresh identity/membership authorization before redisplay. Same-company conversation/module navigation and normal camera background preserve explicitly authored input and frozen pending sends in scoped RAM only; source quotes are freshly fetched or cleared. Logout, account/server/company change, membership/history revocation and confirmed denial clear affected input and owned captures. Process death loses RAM drafts. Media downloads are temporary unless deliberately shared; copied files cannot be remotely revoked. Do not add private offline persistence without an explicit managed-device design.

Voice-note preview/send uses Expo audio. Call audio uses LiveKit's native audio session and Android foreground service; camera/screenshare stop on background. The ongoing call is mounted outside the tabs so navigation does not end audio. Recording/transcription is off. OS incoming-call screens, iOS background/lock behavior, Android background notifications and headset/TURN behavior require physical acceptance. The app's call integration is not evidence that those OS gates passed.

Work/expense decision screens freeze the reviewed version and inspect authorized evidence. A server conflict requires fresh review. Structured responses never call financial/task approvals. Selected publication shows a current server audience and freezes retries; timed work requires an explicit instant/offset and IANA zone. Existing primary claims and independent review remain server-authoritative. Advanced desktop administration, selected exports and split-action declaration remain available through the web application; native feature parity beyond the listed flows is not claimed.

See [communication operations](../docs/COMMUNICATION_OPERATIONS.md) for provider credentials and private signaling. Do not expose LiveKit 7880 directly. Register actual APNs/FCM tokens from the organization's build; generic push hints require operator-owned credentials that are absent here.

See the current [milestone 3 device acceptance script](../verification/mobile-milestone-3/device-acceptance.md) for exact history, calendar, picker and capture scenarios. Every physical gate remains unchecked.
